# 检索排序与冲突回答修正

首次测试中，口语化问题包含“出差”和“报账”，住宿制度因同时匹配差旅与报销而排在报销期限前。
原实现先删除停用词，导致“多久”这一期限意图也被删除。修正为先保留原始分词，再扩展通用同义词：多久、几天、时限对应期限。
回归测试同时保留标准问法和口语化问法，不针对完整问题或文档 ID 改检索逻辑。

首次 Mock 场景中，冲突识别后直接结束，没有演示补查。增加同标题冲突的范围与优先级查询。该规则只存在于 Mock 适配器，不能证明真实模型能力。
失败证据保留在 examples/mock/batch-01/B_conflict/assessment.json 与 D_paraphrase/assessment.json。

真实 batch-01 的冲突回答正确返回待澄清，但附带了“若按最新版本为准”的假设句，容易误导。
系统提示增加禁止无依据的假设性优先级建议，并重新运行批次核对；旧输出保留。

场景断言也增加答案文本中的关键事实检查。引用真实不保证答案正确，自动断言通过后仍需语义复核。

第二轮真实评估 5/8 通过。B 未在读取两份冲突原文后实际补查；D 与 F 则把未问及的起算细节、逾期例外等也视为阻断性缺口，触发 answered 状态校验后变成资料不足或待澄清。
提示明确 gaps 只记录阻断当前问题的缺口，口语起算点与原文不一致时应陈述并纠正为原文起算点；冲突必须在观察后执行实际补查。保留原验收条件与全部失败输出，再重新评估。
