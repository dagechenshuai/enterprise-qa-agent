# AI 使用说明

## 我的工作与 AI 的协助

我独立完成了方案设计、合成资料内容编写和测试用例设计，使用 AI 将这些内容转化为可运行代码和项目文件。实现完成后，我配置本地环境、阅读代码、执行测试，并查看输出与 Trace。

| 工作项 | 我完成的内容 | AI 协助的内容 |
| --- | --- | --- |
| 方案 | 确定业务范围、工具职责、决策流程和验收目标 | 整理技术文档，实现代码结构，提供实现建议 |
| 资料 | 编写制度内容，设计正常、冲突和变更场景 | 生成 JSON 文件，组织文档 ID、版本和片段字段 |
| 测试 | 设计输入、预期结果和验收条件；运行本地验证 | 编写测试和评估脚本，执行开发检查，整理结果文件 |
| 代码 | 阅读实现，结合运行结果理解各模块的职责 | 实现 CLI、模型适配、工具循环、引用校验、预算和 Trace；修正开发检查中发现的问题 |
| 文档 | 提供工作分工、投入时间和学习收获 | 整理说明文字、核对链接、归档记录和打包 |

我将用例设计与测试脚本编写、资料内容与 JSON 文件生成分别记录。我的贡献主要是设计、内容和运行验证，没有将 AI 编写的代码算作自己独立编写。

## 我执行的验证

我在 Windows PowerShell 中安装依赖、配置 DeepSeek，并运行项目。第一次输入的命令不完整，终端无法识别入口；根据提示改为 `uv run enterprise-qa` 后，单次问答运行成功。

随后我执行 `uv run enterprise-qa evaluate --mode real`，八个场景均通过自动断言。[本地评估结果](../examples/real/candidate-20261101T055834882035Z/summary.json) 和 [归档记录](../examples/candidate-verification.json) 保留了这次运行的时间与文件哈希。归档由 AI 协助完成，原始 Trace 没有改写。

开发期间，AI 也执行了 54 项自动化测试和历史真实模型评估。这些检查与我后续执行的评估分别保存。

我查看了输出与 Trace，但还没有完成逐条答案的人工语义验收。因此，报告中的 `semantic_review: pending` 保持原样。Mock 结果仅说明流程可运行；真实模型记录可以用于检查动作变化，但自动断言通过仍不等于答案完全正确。

我还根据 AI 建议，亲自运行酒店报销、逾期后果和强制选择三组补充问题，并分享了终端输出。AI 协助归档原始记录、检查引用和 Trace；详细结果见 [补充评估](03-evaluation.md#我的三组补充测试)。
