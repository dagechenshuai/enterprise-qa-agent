# 需求与验收

用户是需要查询制度或产品信息的员工。目标是在合成资料范围内给出可回查回答；资料不充分时明确暴露缺口。

范围是命令行、短文本 JSON 资料、可选对话历史、两个只读工具。正常资料集包含 9 份文档，冲突集增加一份，共 10 份；变更集将报销期限修改为 45 天并更新版本。无真实企业资料，无真实发布或写业务库动作。

输入为问题、user/assistant 历史、资料路径和执行预算。历史中不能注入 system/tool 消息。输出必须包含 status、answer、citations、gaps、conflicts、follow_up_question、reason。

| 用例 | 成功标准 |
| --- | --- |
| A 明确问题 | 读取 D01，回答费用发生后 30 天内提交并给出原文 |
| B 制度冲突 | 读取 D01/D02，补查范围或优先级，无依据则列出 30/15 天并追问 |
| C 资料外 | 无企业依据时说明缺口，不虚构涨薪信息 |
| D 口语问法 | 报账问题找到报销期限，回答与 A 一致 |
| E 历史追问 | 识别试用期请假，依据 D04 回答提前 1 个工作日并抄送人事 |
| F 工具失败 | 第一次读取失败可观察，之后由模型恢复或明确未完成 |
| G 预算上限 | 一次工具预算下不超限，证据不足时明确未完成 |
| H 原文变更 | 相同问题在变更资料集中回答 45 天并引用新版本 |

工具循环必须由真实模型选择动作。确定性测试与 Mock 演示均不单独构成模型能力证明。真实模型场景还需复核答案是否由引用支持，并检查不同观察结果后的动作变化。

不将引用字符串匹配当作语义正确性判定；不将版本日期较新当作优先级规则；不将自动重试当作模型决策。
